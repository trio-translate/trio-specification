# Glossary

Status: Draft

| Term | Meaning in this specification |
| --- | --- |
| Situation | A real-world context with people, a trigger, constraints, and a desired outcome |
| Condition | A reusable modifier such as music or noise that can combine with multiple situations and other conditions |
| Journey | The ordered experience from entering a situation through completion and recovery |
| Session | A bounded period of product interaction with explicit start/end and data rules |
| Participant | A person taking part; may be a guest without an account |
| Operator / listener | Roles describing device interaction and receipt of output; in the car, the passenger operates and the driver listens without looking at the screen |
| Customer / payer | The person or organization purchasing the service; not necessarily every participant |
| Utterance | A captured speech segment; may initially have provisional recognition results |
| Transcript | Text recognized from speech in the source language |
| Translation | A rendering of source meaning in a target language |
| Clarification | A request or response that resolves ambiguity; never silently attributed to another speaker |
| Explanation | Additional generated context, labeled separately from translation |
| Revision | A new version that explicitly supersedes earlier source text or a translation |
| Source / target language | The language received / the language a particular participant needs |
| Language pair | A directional source-to-target combination; reverse direction needs its own evaluation |
| Turn-taking | The way participants indicate, receive, and relinquish the opportunity to speak |
| Shared device | Participants use one physical device together |
| Same room / co-located | Participants are physically together, with one or multiple devices |
| Remote / hybrid | Participants are apart / some are together and some are apart |
| Capture | Collection of microphone, camera, or typed input for processing |
| Input level | Measured sound level from the selected input stream; distinct from recognized words, speaker identity, or translation quality |
| Word activity | Fresh qualifying recognized human conversation words under a defined policy; never simply microphone amplitude or a processing heartbeat |
| Word-inactivity timeout | Predefined interval without qualifying word activity that can automatically end a session; exact duration/counting policy remains open |
| Logical session | The user's continuing authorized conversation, independent of shorter-lived processing connections or audio engine instances |
| Graceful recovery | Restoring useful participant capabilities automatically and truthfully, with explicit gaps when the original outcome cannot be preserved |
| Offline-ready | All processing/resources/authorization required by the selected situation are available without runtime connectivity |
| Playback | Device output of synthesized or replayed audio |
| TTS | Text-to-speech generated by Trio; its mute policy is separate from microphone capture and system accessibility speech |
| Retention | Keeping data after its immediate processing purpose ends |
| Supported | A published capability with defined quality coverage and verified operation |
| Draft / Proposed / Agreed / Superseded | Maturity of specification content, not implementation or release status; a superseded record stays in place with a link to its replacement |
| Candidate launch | Proposed for the first release, awaiting scope agreement |

Product and technical documents should use these terms consistently. Add terms when they resolve actual ambiguity.
